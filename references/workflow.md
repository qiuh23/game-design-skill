# 施工、上线与验收

1. 确认范围和来源：定位实际生效的 CSS 与组件，已验收的实例才可作模板。布局改动只触及样式与展示层，不改规则、状态、网络协议或服务端。
2. 合并重复定义时先核对级联；与目标无冲突时保留实际生效的那份，冲突时按新设计改。删除前用 grep 核对引用，动态类名另看调用路径；每个组件保留清楚的样式归属。
3. 旧测试与新设计冲突，可以重写成检验新目标的测试。没有改变的行为仍要检验；不能把测试通过当成渲染证据。
4. 一阶段一 PR，列出逐项改前／改后与构建测试。可按授权在测试、双站构建通过后合并部署，核对两站线上版本。记录截图和实测的区别；本轮明确跳过或受限的截图不拦截合并，不虚报已检查。
5. 合并部署后报告并停下等 Qiu。涉及布局时，必须由 Qiu 在真机看线上实际效果并确认，才算验收完成；截图、DOM、测试和部署记录都不能替代。被否决，整 PR revert，不在被否决的提交上叠改。

反面判例：2026-11-15 的首页对齐只核对了代码与文案，线上才发现运动会规则图标被标签挤坏、卡坦手机布局异常；三个对齐改动分别以[运动会 #86](https://github.com/qiuh23/magical-athlete-online/pull/86)、[卡坦 #38](https://github.com/qiuh23/catan-friends/pull/38)、[巫师 #55](https://github.com/qiuh23/wizard-friends/pull/55)回退。回退与改版 v2 推翻整轮对齐；v3 又替代 v2 的内嵌表单与整宽按钮写法。该保留的是验证过的裁决，不是被回退的实现。
